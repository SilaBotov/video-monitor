# Video Monitor

Круглосуточный мониторинг веб-генераторов видео на ИИ: находит новые платформы и изменения
бесплатных условий, проверяет их по официальным сайтам и присылает отчёт в Telegram.

Работает целиком на GitHub Actions: свой сервер не нужен, всё бесплатно (Groq API — free tier).

## Что отслеживается

Отбор идёт по тем же критериям, что и в Google-мониторинге:

- **Только браузер.** Сервис должен работать напрямую на сайте; инструменты только через
  Discord или Telegram-бота исключаются.
- **Бесплатный доступ.** Стартовые кредиты при регистрации, ежедневно возобновляемые квоты,
  пробный период или безлимитное демо. Привязка карты — не препятствие, но отмечается в карточке.
- **Лимиты и тип квоты.** Объём в секундах/генерациях/токенах; `daily`, `monthly`, `trial`,
  `rolling` (скользящие циклы).
- **Форматы и качество.** 9:16 (Reels/Shorts/TikTok) в приоритете, плюс 16:9; бесплатное
  разрешение 480p / 720p / HD / Full HD.
- **Водяные знаки** на бесплатном тарифе.
- **Режимы.** Image-to-Video, Start & End Frame, ИИ-липсинк, нативный звук, Consistent Characters.
- **Модели.** Появление Kling, Sora, Veo, Seedance, Wan, MiniMax и других флагманов внутри сервиса.
- **Спецтриггер NotebookLM.** Отдельно проверяется появление полноценного художественного
  видеогенератора по свободному промпту, независимого от загруженных документов.

## Как устроен пайплайн

1. **Поиск.** Google News RSS + DuckDuckGo News/Web, фильтрация мусора и нерелевантных тем.
2. **Разбор.** Groq (`openai/gpt-oss-120b`) выбирает из находок реальные запуски и изменения
   условий и возвращает строгий JSON.
3. **Проверка на сайте сервиса.** Для каждого кандидата находится официальный сайт, читаются
   главная и страницы тарифов; второй запрос к Groq подтверждает бесплатный доступ и лимиты.
   Без подтверждения на официальном сайте карточка не публикуется.
4. **Формирование отчёта.** Текст переписывается строго по проверенным данным, переводится на
   русский, отправляется в Telegram; обработанные сервисы попадают в `state.json`.

## Быстрый старт на GitHub

### 1. Репозиторий

Залейте содержимое этой папки в репозиторий на GitHub (или сделайте fork). Структура:

```
monitor.py
requirements.txt
state.json
README.md
.github/workflows/monitor.yml
```

### 2. Ключ Groq

1. Зарегистрируйтесь на [console.groq.com](https://console.groq.com).
2. **API Keys → Create API Key**, скопируйте значение (`gsk_...`).

Ключ бесплатный, карта не нужна.

### 3. Telegram-бот и chat_id

1. В Telegram напишите [@BotFather](https://t.me/BotFather), команда `/newbot`, получите токен
   вида `123456789:AA...`.
2. Напишите своему боту любое сообщение (иначе он не сможет писать вам первым).
3. Узнайте `chat_id`: откройте
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id":...}`.
   Для канала или группы id отрицательный (`-100...`), бот должен быть там администратором.

### 4. Секреты репозитория

**Settings → Secrets and variables → Actions → New repository secret** — добавьте три секрета:

| Имя | Значение |
|---|---|
| `GROQ_API_KEY` | ключ из п. 2 |
| `TELEGRAM_BOT_TOKEN` | токен бота из п. 3 |
| `TELEGRAM_CHAT_ID` | id чата/канала из п. 3 |

### 5. Права на запись

**Settings → Actions → General → Workflow permissions** → выберите
**Read and write permissions** и сохраните. Без этого не получится коммитить `state.json`
(по умолчанию GitHub выдаёт read-only, и шаг с `git push` упадёт).

### 6. Включите и проверьте

1. Вкладка **Actions** → если workflow отключён, нажмите **Enable workflow**.
2. **Video Monitor → Run workflow**, поставьте `dry_run = true` и запустите.
3. В логе будет напечатан готовый отчёт, но в Telegram ничего не уйдёт и `state.json` не изменится.
4. Если всё ок — запустите ещё раз с `dry_run = false` (или дождитесь расписания).

## Расписание

```yaml
- cron: '0 */6 * * *'   # каждые 6 часов, время UTC
```

GitHub Actions работает по UTC, а Екатеринбург — UTC+5. Чтобы отчёт приходил в удобные часы,
ставьте, например, `0 2,8,14,20 * * *` UTC — это 07:00, 13:00, 19:00 и 01:00 по местному времени.

Частоту можно увеличить (`0 */2 * * *` — каждые 2 часа), но учитывайте лимиты Groq free tier:
один прогон делает ~8–12 запросов к модели.

## state.json

Файл хранит историю отправленного, чтобы не присылать одно и то же дважды:

```json
{
  "seen": [
    {
      "name": "Сервис",
      "domain": "service.com",
      "date": "2026-11-07",
      "sig": {"nums": ["20"], "models": ["veo"]}
    }
  ]
}
```

- Дубли (одна пара «название + домен») автоматически схлопываются при загрузке и сохранении.
- Хранится не больше 1000 последних записей.
- Повторный сервис попадёт в отчёт только как `updated` — если изменились бесплатные лимиты,
  режимы или видеомодели.
- Поле `sig` — отпечаток условий (числа из лимитов + модели). По нему проверяется, что
  «обновление» действительно что-то меняет, а не пересказывает прошлую отправку.
- Сбросить историю: заменить файл на `{"seen": []}`. Тогда все сервисы снова считаются новыми.

## Защита от мусорных карточек

Промпт запрещает многое, но модель может ошибиться, поэтому после неё работает детерминированная
проверка (`sanitize_items`, `filter_unconfirmed_updates`, `has_data`):

- **Деньги не считаются бесплатным лимитом.** Фразы вида «пакет на $1 млн кредитов» вырезаются,
  а карточка без описания реального изменения не публикуется.
- **«Без ограничений» и «безлимит»** удаляются из текста: это домысел, если в источнике нет
  прямого подтверждения.
- **Нужен измеримый объём**: кредиты, секунды, ролики, генерации. Карточка «кредиты при
  регистрации, количество не указано» в отчёт не попадёт.
- **Текстовые модели** (GPT, Claude и т.п.) выбрасываются из списка видеомоделей.
- **Повторные «обновления»** проходят только при реальном изменении: другие числа в лимитах
  или новые модели. Иначе сервис повторно не отправляется.

Всё это настраивается константой `REQUIRE_FREE_VOLUME` в `monitor.py`: `False` возвращает
более мягкий режим (публикуем всё, что подтверждено как бесплатное).

## Локальный запуск

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

export GROQ_API_KEY=gsk_...      # Windows: set GROQ_API_KEY=gsk_...
export TELEGRAM_BOT_TOKEN=...    # для dry-run не обязательно
export TELEGRAM_CHAT_ID=...

python monitor.py --dry-run      # полный прогон без отправки и без записи истории
python monitor.py                # боевой запуск
```

`--dry-run` (или `DRY_RUN=1`) прогоняет весь пайплайн, но только печатает сообщение. Удобно,
чтобы проверить качество отчёта и не спамить канал.

## Ограничения и что важно знать

- **Сайты на JavaScript.** Многие лендинги отдают пустой HTML без браузера. Если текст короче
  300 символов, сервис помечается как непроверенный и в отчёт не попадает — это защита от
  выдуманных лимитов, а не ошибка.
- **Лимиты Groq.** На free tier возможен `429`: скрипт ждёт 30 секунд и повторяет запрос один раз.
  Если ошибка повторяется, следующий прогон по расписанию подхватит новости.
- **Ложные срабатывания.** Модель может принять рекламный пресс-релиз за запуск; такие тексты
  помечаются в карточке как «заявление самого сервиса, не проверено».
- **Задержки расписания.** GitHub может запускать cron с задержкой в 5–20 минут, а после
  60 дней без активности в репозитории — вообще отключить расписание. Любой ручной запуск
  или коммит это лечит.
- **Приватность.** В отчёте не должно быть секретов; ключи хранятся только в Secrets и в логи
  не печатаются.

## Если что-то не работает

| Симптом | Причина | Что делать |
|---|---|---|
| `Не задан GROQ_API_KEY` | секрет не добавлен или пустой | проверить Settings → Secrets |
| `401` / `403` от Groq | ключ отозван или неверен | создать новый ключ |
| `400` от Telegram | неверный `chat_id` или бот не в чате | написать боту / добавить в канал |
| Отчёт пустой месяцами | слишком строгие фильтры или мало запросов | добавить запросы в `search_and_parse()` |
| `git push` падает | нет прав на запись или включена защита ветки | Settings → Actions → General → Read and write; снять protection с ветки |
| Сервис не в отчёте | не найден официальный сайт | проверить `KNOWN_SITES` в `monitor.py` |

## Файлы

- `monitor.py` — весь пайплайн: поиск, анализ, проверка сайтов, отправка.
- `requirements.txt` — зависимости Python.
- `state.json` — история отправленных сервисов.
- `.github/workflows/monitor.yml` — запуск по расписанию и вручную.
